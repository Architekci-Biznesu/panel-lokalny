Zasady

Toast vs alertToast = wynik akcji albo stan procesu. Alert = stała informacja w treści strony.
Procesy = promiseAnaliza: loading → success/error w tym samym toaście, bez osobnego bannera.
Przyciski w toaścieZawsze neutralne (szara pigułka, ciemny tekst), niezależnie od stanu. Błąd z akcją (Otwórz Integracje) nie znika sam.
Tytuł = wynikZdanie, bez kropki, ciemny. Kolor tylko w ikonie.
Opis = kontekstKtóre pole, ile rzeczy albo treść błędu z API.

Nadpisanie w globals.css

Tylko zmienne biblioteki - wywołania toast.success / .error / .promise zostają jak dziś.
:root {
  --gooey-state-success: #16a34a;
  --gooey-state-error: var(--destructive);   /* #e7000b */
  --gooey-state-warning: var(--warning-foreground); /* #e5582b */
  --gooey-state-info: #6366f1;
  --gooey-state-loading: var(--muted-foreground);
  --gooey-state-action: var(--primary);
}
[data-gooey-toast] { font-family: var(--font-sans); }
[data-gooey-title] { color: var(--foreground); font-weight: 500; text-transform: none; }
[data-gooey-description] { color: var(--muted-foreground); font-size: 13px; }
